# Aurelle

A premium local shopping app for a family business in India. **Stage 1 (foundation)**: branded,
responsive, installable homepage with an offline-capable app shell. No products yet.

Stack: React 19, TypeScript (strict), Vite 7, plain CSS with design tokens, Playwright tests.
Requires **Node.js 22.12 or newer** (`.nvmrc` says 22).

## Run it locally

```bash
npm install        # first time only; creates package-lock.json (commit it)
npm run dev        # development server with live reload -> http://localhost:5173
```

To try it on your Android phone on the same Wi-Fi: `npm run dev -- --host`, then open the
"Network" address it prints. (The service worker only runs in production builds.)

## Build and test

```bash
npm run build      # type-check + production build + service-worker generation -> dist/
npm run preview    # serve dist/ locally -> http://localhost:4173
npm run test:install   # one-time: download the test browser (Chromium)
npm test           # browser tests against the production build (run `npm run build` first)
npm run verify     # build + test in one go (what GitHub Actions runs)
```

## Put it on GitHub

1. Create an empty repository on github.com (no README, no .gitignore). Name it e.g. `aurelle`.
2. In this folder:
   ```bash
   npm install                      # creates package-lock.json
   git init -b main
   git add .
   git commit -m "Stage 1: Aurelle foundation"
   git remote add origin https://github.com/YOUR-USERNAME/aurelle.git
   git push -u origin main
   ```
3. Open the repository's **Actions** tab. The **Verify** workflow runs on every push and pull
   request. A green tick means it type-checked, built and passed all browser tests. The finished
   `dist` folder is attached to each run as the `aurelle-dist` artifact.

Never commit passwords, API keys or `.env` files (`.gitignore` already blocks them).

## Deploy (separate from GitHub Actions)

The workflow only *verifies*; it does not publish anything. To publish, upload the `dist/`
folder (from `npm run build`, or the `aurelle-dist` artifact) to any **HTTPS** static host:

- **Cloudflare Pages / Netlify**: connect the repository, build command `npm run build`,
  output folder `dist`. Or drag and drop the `dist` folder.
- **GitHub Pages** (project site): build with the repository name as the base path, e.g.
  `BASE_PATH=/aurelle/ npm run build`, then publish `dist`.

Installing as an app ("Add to Home screen") and offline support need HTTPS.

## Offline behaviour (what it does and does not do)

After one successful online visit, the app shell (page, styles, scripts, icons) opens without a
network. Pages try the network first so updates are never stale, and fall back to the cache when
the network is slow (4 s) or gone. Nothing else is cached: product data and images, when they
arrive in later stages, will need an internet connection. New deployments install automatically,
old caches are deleted, and the page reloads once to pick up the new version.

## Stages

- **Stage 1 (done)**: foundation, brand, responsive homepage, PWA shell, CI.
- **Stage 2**: categories, product listings, search, product-detail pages (labelled sample data until real inventory exists).
- **Stage 3**: call / enquire workflow (needs the business phone number and contact details).
- **Stage 4**: secure admin for products (database, image storage, real authentication; e.g. Supabase).
- **Stage 5**: deployment and testing on real Android devices, performance and accessibility tuning.

Not built and not faked: products, prices, contact details, cart, admin screen, accounts, payments.
